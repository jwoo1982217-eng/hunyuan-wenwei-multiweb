## 二、文心参考图注入（核心方案，chat/生图/视频通用）

### 2.1 为什么文心特殊（CDP 受控实验结论）

文心的文件 input（`.chat-input-function-file`）**只接受 isTrusted=true 的 change 事件**：

| 注入方式 | change 事件 | 页面反应 |
|---|---|---|
| JS DataTransfer + dispatchEvent | `isTrusted=false` | ❌ 完全忽略（files=1 但零网络）|
| CDP `DOM.setFileInputFiles` | `isTrusted=true` | ✅ 走上传链（PC 端验证）|
| **真实触摸 + 原生选择器** | `isTrusted=true` | ✅ **App 内唯一可行**（PC 的 CDP 方案 App 内不可用）|

### 2.2 最终可行路径（三通路统一）

```
真实触摸 "+"（.cs-input-plus-btn，MotionEvent 直发）
  → 菜单弹出（相机/相册/文件/打电话）
  → 真实触摸 "相册"（.chat-input-function-item 内的图标）
  → WebView 原生 onShowFileChooser 触发
  → NativeWebFileChooserBridge 喂文件（onReceiveValue 回调）
  → 页面自走上传链：/api/file/sts → bcebos 分片 PUT → /api/file/upload
  → 附件 chip 出现（.cs-input-file-container）
  → [兜底] 触摸路径失败 → JS DataTransfer 注入（此时页面会接受，因 change 已被原生桥激活）
```

### 2.3 坐标模型（血泪教训）

- `dispatchTouchEvent` 用 **WebView 局部坐标 = CSS × density**，**不能加 getLocationOnScreen 偏移**
  （加了会点到可视区外——本轮为此浪费数小时；adb 系统坐标 = CSS×dpr + WebView屏幕偏移，两者不同）
- 坐标必须**点击前一刻实时读取**（`getBoundingClientRect` 视口坐标随页面滚动漂移，实测漂移 100px+）
- 点击后校验菜单是否打开，失败重试（3 次）

### 2.4 心跳发送（chat 专用）

文心是 React 站点，合成 click 对发送按钮无效。方案：
- 后台线程等"附件 chip 就绪 + 输入框有文字"
- 心跳：读 `.cs-input-ds-send-btn` 中心 → **真实触摸** → 校验输入框清空（`textarea.value === ''`）
- 清空即成功；失败重试 12 拍（每拍 1.3s）

### 3.2 smali 补丁

| 补丁 | 文件 | 内容 |
|---|---|---|
| patch29 | `CustomWebChatAutomation.smali` | chat 调用点前插文心分支（零寄存器：仅 `invoke-static`）|
| patch30v2 | `CustomWebImageAutomation.smali` | 生图注入点插 `invoke-static {v2}`（v2=refImages，零新寄存器）|
| patch31 | `CustomWebVideoAutomation.smali` | ① 6905 行前 `move-object/from16 v1, v20` + `invoke-static {v6, v1}` 暂存 refs；② `:cond_4` 入口 `invoke-static {}` 触发注入 |

**关键教训（防 VerifyError）**：
- 往 coroutine 状态机里插分支（if-eqz 等）会导致 ART 验证器拒绝整个方法（`register type Conflict`）——本轮踩了两次
- **正确做法：把逻辑全部内聚到 Java 侧，smali 只插无分支的 `invoke-static`（零新寄存器）**
- `move-object` 的 12x 格式只支持 v0-v15，从 v16+ 取值必须用 `move-object/from16`
- Java 方法参数类型必须与 smali 调用签名**完全一致**（本轮 `Object` vs `CustomWebProviderConfig` 导致 NoSuchMethodError → 500）

## 四、构建注意事项（踩坑合集）

1. **d8 必须传全部 class**（含 `$1`/`$2` 等匿名内部类），漏传 → `NoClassDefFoundError`
2. **javac 用 stub 目录**：`-classpath android.jar;tmp_javaclass/stubs`，stub 只给 javac 看，**不要**把 stub 的 class 传进 d8
3. **覆盖 decoded 树前先删旧 WenxinAttachmentUploader*.smali**（类结构变了会残留）
4. smali 文件禁用 PowerShell 读写（BOM/CRLF），一律 Python
5. apktool 打包前确认 smali 无语法错（`Invalid register` / `Could not smali file` 会在 b 阶段才报）

## 七、本轮教训增量

1. **用户手动操作是金标准**：文心的"原生选择器路径"就是用户手点出来的；CDP 实验只用于确认原理，最终方案必须是 App 内可执行的
2. **"UI 没变就别查结构"**（用户原话）：chat 和生图/视频的输入区是同一个组件，注入方式完全通用——不要重复做页面结构调研
3. **VerifyError 排查**：报 `register vN has type Conflict` 就是插入了破坏类型流的分支——改用"Java 内聚 + 零寄存器 invoke"模式
4. **心跳模式复用**：patch20/21（文心视频心跳发送）→ 本轮 chat 心跳发送 → 一脉相承，模式是"`__go` 封装 + tick 重跑 + 成功信号即停"
5. **无参静态调用是 smali 补丁的终极安全区**：`invoke-static {}` 不碰任何寄存器，能最大程度规避验证器问题
